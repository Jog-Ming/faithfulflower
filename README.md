# faithfulflower

faithfulflower is a fork of [Vineflower](https://github.com/Vineflower/vineflower) built around a
different objective. Vineflower aims for the most readable decompilation; faithfulflower aims for
the most faithful one: the generated Java, compiled again with javac, must reproduce the original
class file byte for byte — instructions, line tables, local variable tables, signatures, annotations
and every other attribute.

## How it differs

- Decompilation is one Vineflower run followed by deterministic passes that decide from the class
  file alone. Nothing compiles during decompilation and no class file is ever written.
- The verifier is the only judge: a repair counts when the regenerated bytes match the original jar.
- Output forms are taken from ground-truth trees — verified sources whose recompilation is identical
  to the input — instead of being re-derived from bytecode.

## AI assistance and upstream

faithfulflower is developed with AI assistance: research, implementation and measurement are
carried out together with Claude (Anthropic's Claude Code), and this README is written by AI. Every
decompile is a deterministic Vineflower run followed by deterministic passes, and the verifier
decides every change byte for byte.

This work will not be merged back into Vineflower. The goal is different — faithfulness to the
original bytecode rather than readable output — and upstream's AI use policy does not permit it.

## Status

For Minecraft 1.21.11 and the 26.1, 26.2, 26.3 and 26.4 snapshot Java editions, every class
decompiles, compiles and verifies identical (`fully == classes`, `missing == 0`), and the quality
counters (raw uses, double casts, unchecked conversions) match the corresponding ground-truth tree.

## Use

Build:

```
./gradlew build
```

The decompiler jar lands in `build/libs/faithfulflower-<version>.jar`. It runs like Vineflower:

```
java -jar build/libs/faithfulflower-1.13.0+local.jar <arguments> <source> <destination>
```

## The experiment pipeline

`devtools/cli` downloads the target jars, decompiles them, compiles the result with javac and
compares classes attribute by attribute. Its caches live under `.dev/` and are disposable.

```
devtools/cli versions
devtools/cli decompile <version>
devtools/cli score <version>
devtools/cli diff <version> <Class> --full
```

`CLAUDE.md` documents the full interface and the rules the fork is held to; `ARCHITECTURE.md`
describes the decompiler itself.
